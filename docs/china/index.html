Разделение заказа при частичной поставке

Ровно ваш кейс из ТЗ: артикул IRA-KTM-1 заказан на 1000 шт, фабрика прислала на склад 700. Система откалывает пришедшую часть в дочерний артикул, а остаток остаётся «в производстве».

Логика: если «Пришло сейчас» < «Заказано» — создаётся дочерний артикул с суффиксом (IRA-KTM-1 → IRA-KTM-1-1) на пришедшее количество со статусом «на складе», а родительский артикул остаётся с остатком и статусом «неполный заказ» с собственным сроком производства. Оплаты, себестоимость и упаковка считаются по каждому артикулу отдельно — это то самое, из-за чего в старой системе путаница.

Упаковка в смешанные короба

Один короб может содержать несколько артикулов разного веса. Перетащите позиции из пула в короба — габариты, вес и плотность короба считаются автоматически по вложенным позициям.

Плотность = вес / объём. Если плотность выше 100 — доставку считаем по весу, если ниже — по объёму (правило из вашего ТЗ). Смешанный короб может перевернуть эту логику: лёгкий, но объёмный товар в одном коробе с тяжёлым меняет способ расчёта для всего короба, и это надо увидеть до отгрузки, а не после.

Распределение платежей по заказу

Один платёж от клиента (в рублях) закрывает авансы/остатки/доставку сразу по нескольким артикулам, в разных валютах. Демо показывает, как один приход автоматически распределяется по строкам заказа.
